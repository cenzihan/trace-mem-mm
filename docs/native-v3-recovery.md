# 第 12 批响应的恢复审计

原请求为 HTTP200，返回指定模型和有效 usage（25703 输入、416 输出 token），
总分类 invalid_contract。已保存十一批响应的结构均通过冻结的契约和图像项校验。
第十二批未保存响应体，因此无法离线判断具体拒绝分支，也不能补造图像卡片。
没有读取受限会话文件、凭据源文件或进程内存来寻找响应。

新增 `response_diagnostics` 将冻结校验器拒绝原因划分为 choices 形状、finish reason、
refusal、tool calls、非 JSON、summary 类型、evidence_quotes 类型等有限代码。
诊断记录只含状态码、长度和有限代码，不含源内容、任意响应字符串或秘密。
fakeHTTP 已验证各分支与原校验器接受/拒绝一致，没有放宽事实校验或改变模型提示词。
对已审核公开输入，可显式开启仅限 HTTP200 指定模型返回字段的私有隔离缓存，
方便未来离线修解析；错误体、headers 和未知额外字段不留存，缓存不进日志或 Git。

新增明确恢复操作只允许核实为 HTTP200、已知指定模型、usage 未超界的
invalid_contract 记录成为 `rejected_response`，原失败槽位、预算占用和关联仍保留。
超时、无 usage、非200、模型异常或超限继续阻止后续请求。
这不把失败改成成功，也不会释放预占或自动重发。

原响应无法恢复时，需要一次新的有账本补采，才能补齐缺少的三张图。
准备好的恢复入口复用十一批有效缓存，沿用同一个 100 次/20 元 guard；
含这次新请求的完整计划为 84 次/12.20 元，新增剩余计划最多72次/9.20元预占。
A/B/C、视觉、reader 和 judge 提示词都保持冻结。旧停止报告不覆盖。
