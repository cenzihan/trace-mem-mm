# 第二场景：无新调用的误差诊断

这是冻结输出的事后诊断，不是新评测，不用于改同题 prompt 追分。
原 84 次场景 guard 保持 complete，项目提供商请求保持 168 次。
脚本`analyze_native_v3_trace.py`只读已保存向量、原索引和答案，在独立分析进程
读取 gold。先复现全部 77 题×3 组=231 个 Top20，与历史记录逐项一致，才检查缺失项。
原结果、共享预算、场景 guard、Smoke 账本的文件 hash 在分析前后相同。

## 候选到 reader

20 份 reader 输入都保留完整 20 个 round，A/C 最多 3239/3314 文本 token。
因此这次**没有文本预算截断，也没有 gold 在装包阶段丢失**。
不能用“8192 token 不够”解释本轮错误。

在十题各自的已打包上下文里，A/C 都包含 8 个“标注 gold round 中的图像 occurrence”。
实际送给 reader 的分别是 6/5 个，遗漏 2/3 个。代码沿检索顺序选择最先出现的图片，
统一最多两张；它没有专门的 query-aware 选图步骤。
这是可观察的选图损失；原标注是 round 级，不能证明该 round 每张图都不可替代。

已打包但未列作引用的 gold round，A 合计 3 个、C4 个。引用上限为 3，
而某些题 gold 多于 3 条，因此引用召回存在结构上限。
未引用不证明模型内部未使用；别名合法也不证明它支持了回答。
选图并非全部错误的解释；单次随机输出与上下文顺序/干扰无法在本诊断中分离。

## 跨 session 检索的失败类型

诊断发现，RRF 融合可能压低单一强通道中的证据，使其落在固定 Top20 外。
局部 top5 seed 的来源覆盖有限，缺少 grounded visual entities 的来源也无法由
现有视觉实体邻居通道补回。有限的邻居 boost 不保证跨来源证据进入候选集。
当前实体数组主要来自视觉标签，缺少可泛化的文本实体通道。
**没有调整 RRF 权重、seed 数、K 或邻居权重后重报分数**。

## 拒答与支持充分性

现有实现校验字段类型和别名，未证明回答被证据支持。自报 supported 和给出合法
别名不足以证明答案正确；规范拒答字符串也未由 decoder 作为条件式约束强制执行。
这个格式诊断不改变既有语义判分或历史“schema 类型合法”记录。
因此“检索完整”“可引用”“回答正确”必须分开计量。
gold 可能不穷尽所有支持来源，单次代理 judge 也不是因果审计，不能直接把每次
未命中 gold 都称幻觉。

## 下一步的限制

本轮只新增诊断代码和 source-only 适配契约，没有修改冻结检索/reader 或重新生成答案。
在独立数据上再检验：细粒度检索后绑定原始证据、显式模态路由、受限选图、
来源级去重和支持不足策略。强参考配置及预算另见`strong-baseline-review.md`
与`next-independent-evaluation.md`。本报告不是用 oracle 标签实现新的选图器。

逐题编号、具体排名、gold、命中及正确性明细仅保留在原实验项目的私人
`reports/native-v3-error-audit.json` 和 `reports/native-v3-scores.json`，不随导出分发。
