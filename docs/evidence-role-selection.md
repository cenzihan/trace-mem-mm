# One-pass original evidence roles

Independent synthetic controls repeatedly retrieved both an identity source and
a location source, but selected only the latter. In one control both originals
were fully visible, so enlarging text prefixes alone was insufficient. This
does not establish the cause of any protected benchmark error.

The opt-in v4.7.1 candidate asks one bounded model call for two index arrays:
`identity` sources establish the query subject or explicit alias connection;
`facts` sources support the requested attribute, event, or compared states.
The selector returns fact indices followed by previously absent identity indices,
at most eight distinct original sources. One source may serve both roles.
These labels are model judgments, not verified semantic proofs. The rc3 policy
returns a normal empty selection when no requested-fact source was selected:
identity alone does not establish the asked attribute or event. Both arrays
are validated first. The service does not fabricate a missing fact, retry for
a desired semantic result, or permanently block on semantic incompleteness.

The official response remains the original `data` source list. No answers,
generated entities, quotations or graph dependencies are added. The candidate
uses the baseline 1500-byte views, 32-source pool and eight-image budget. It does
not activate the experimental extended-view or identifier-support selectors.
Original memory storage, neighbour packing, image identity behavior, billed
retries, journal history and model identity checks remain unchanged. Packing
and visual coverage are separate hypotheses, not claimed fixes here.

Required independent checks include a pure-name identity bridge, near-name and
denied-identity distractors, time comparison, direct recall and absent facts.
Mechanical validity alone cannot establish retrieval quality or score gains.

The first independent real control for rc1 passed direct recall but returned
identity alone for a pure-name bridge, omitting the visible location source.
It was stopped and never deployed. The rc2 hypothesis adds three original
synthetic demonstrations of cross-source roles, a direct source serving both
roles, and denied identity. It preserves all response shapes and capacities.
This is a new, unvalidated hypothesis rather than a claim that examples fix
semantic completeness; new controls must detect copied indices and false links.

The rc2 independent control retrieved both identity and location for a pure-name
bridge, but returned identity-only evidence for a denied-identity question.
It was stopped and never deployed. The rc3 empty-facts rule is a distinct
retrieval hypothesis requiring fresh positive and negative controls. It does
not prove calibration, nor remove inherited exact-image/adjacent-source paths.

Factory: `agent_memory.evidence_roles:create_role_app()` with explicit
`TRACEMEM_EVIDENCE_ROLES_ENABLED=approved-original-evidence-roles` activation.
